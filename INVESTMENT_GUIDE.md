## 1. ANALYSE DU MARCHÉ

### 1.1 Contexte Macro — Maroc

| Indicateur | Valeur |
|---|---|
| Population | ~38 millions (2026) |
| Moins de 35 ans | 65%+ |
| Pénétration Internet | ~90% |
| Pénétration Smartphone | ~78% |
| Marché e-commerce | ~$3.5B (croissance 30%+ par an) |
| Déchets solides annuels | 7M+ tonnes |

### 1.2 Signaux de Demande

- **Avito.ma** reçoit 10M+ visites mensuelles — preuve que les Marocains achètent/vendent activement en ligne
- **Facebook Marketplace** et les groupes **WhatsApp** sont massivement utilisés pour le C2C, mais sans protection acheteur, ni infrastructure de paiement, ni confiance
- Le marché mondial de la seconde main atteindra **$350B d'ici 2028** (ThredUp). Le Maroc est un candidat naturel
- La consommation de seconde main est culturellement ancrée (souks, marchés de frip, ventes de garage), mais **largement non digitalisée**

### 1.3 Pourquoi Maintenant

- L'adoption digitale post-COVID est permanente
- Sensibilisation environnementale croissante chez les jeunes Marocains
- Politique gouvernementale pro-digitale (Stratégie Maroc Digital 2030)
- Infrastructure de paiement en ligne en maturation (CMI, Maroc Telecommerce, HPS)
- Inflation et hausse du coût de la vie poussent les consommateurs vers des alternatives abordables

### 2.1 Comparaison Directe

| Critère | Avito | Facebook Marketplace | Jotya |
|---|---|---|---|
| **Confiance & vérification** | Faible (pas de vérification vendeur) | Aucune | Certification vendeur + vérification produit |

- Catégorisation produit professionnelle
- Supervision admin complète
- Authentification des produits de valeur

**Positionnement :** Plus proche de Vinted/Depop que d'Avito. Premier du genre au Maroc.

## 3. MARCHÉ CIBLE

### 3.1 Segment Primaire — L'Acheteur Malin (18–35 ans)

- Urbain, digital native, sensible au prix
- Actif sur Instagram, TikTok, WhatsApp
- À l'aise avec l'achat en ligne mais frustré par les arnaques sur les canaux informels
- **Villes :** Casablanca, Rabat, Marrakech, Tanger, Fès, Agadir
- **Revenu disponible mensuel :** 1 500 – 5 000 MAD
- Cherche la qualité à prix réduit, la durabilité est un bonus

### 3.2 Segment Secondaire — Le Micro-Entrepreneur (20–40 ans)

- Individus qui achètent/revendent de la seconde main comme revenu complémentaire
- Petits commerçants cherchant une vitrine en ligne abordable
- Actuellement sur Instagram/WhatsApp avec zéro infrastructure
- Prêts à payer une commission si la plateforme apporte du trafic et de la confiance

### 3.3 Segment Tertiaire — L'Éco-Conscient / Amateur de Luxe (25–45 ans)

- Tranche de revenu supérieure
- Attirés par les catégories curées ("catalogue luxe", "pièces uniques", "marques rares")
- Prêts à payer des frais d'authentification pour des articles de luxe vérifiés

## ANNEXE A: ANALYSE TECHNIQUE — DASHBOARD ADMIN

### A.1 Architecture d'Authentification

**Comment ça marche :**

```
FLUX D'AUTHENTIFICATION JOTYA:

1. Utilisateur va sur /dashboard/admin
2. AdminGuard vérifie authentification
3. Si non connecté → Redirect /login
4. Login Component affiche formulaire
5. AuthService valide credentials
6. Token JWT stocké en localStorage
7. User redirigé vers dashboard admin
```

### A.2 Problème Fréquent : Login Disparaît

**DIAGNOSTIC DU PROBLÈME :**

Le problème "login s'affiche qu'une fois" est causé par:

| Cause | Symptôme | Solution |
|---|---|---|
| **Token en cache** | Page login ne s'affiche plus après première connexion | Vider localStorage |
| **Guard mal configuré** | Redirection infinie entre /login et /dashboard | Vérifier adminGuard |
| **SSR/Browser mismatch** | Comportement différent server vs client | Vérifier isPlatformBrowser |
| **Token expiré** | Connexion automatique puis déconnexion | Vérifier expiration token |

### A.3 Code Debug — Vérifications

**1. Vérifier l'état d'authentification :**


### A.8 Architecture Complète

```
JOTYA DASHBOARD ARCHITECTURE:

Frontend (Angular 21)
├── Guards: adminGuard (protection routes)
├── Services: AuthService (JWT + role management)  
├── Components: Login + Admin Layout + Pages
└── Storage: localStorage (token persistence)

Backend (Supabase)
├── Authentication: JWT tokens
├── Database: Users, roles, permissions
└── API: Login/logout endpoints

Flow:
User → Login → AuthService → Token → Guard → Dashboard
```

Cette architecture garantit:
- ✅ Sécurité (routes protégées)
- ✅ Persistance (localStorage)  
- ✅ Rôles (admin vs user)
- ✅ SSR compatibility
- ✅ Error handling
